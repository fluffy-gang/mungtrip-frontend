# 멍멍트립 Play 심사 최소 버전 PRD

## 문제

완성 앱 개발과 Google Play 신규 앱 검토를 순차적으로 진행하면 출시 일정에 심사 대기 시간이 추가된다. 신규 개인 개발자 계정은 프로덕션 접근 신청 전에 12명 이상의 테스터가 14일 연속 참여하는 비공개 테스트를 완료해야 하므로, 현재 서비스 방향을 유지하는 작고 완결된 버전을 먼저 배포할 필요가 있다.

현재 홈은 지도, 장소 정보, 추천 코스, 개인화와 아직 동작하지 않는 탭을 함께 노출한다. 이 상태로 제출하면 스토어 설명과 실제 기능이 불일치하거나 핵심 흐름이 미완성으로 보일 수 있다.

장소 수가 적은 상태에서 마커만 배치하면 사용자가 지도를 움직여 장소명을 확인하는 것 외에 얻는 효용이 약하다. Google Play의 제한된 기능·콘텐츠 정책은 특정 장소 수를 합격 기준으로 제시하지 않지만, 콘텐츠가 매우 적거나 앱다운 상호작용과 효용이 없는 제품은 허용하지 않는다. 따라서 이 버전은 장소 수를 부풀리거나 미완성 기능을 추가하는 대신, 동일한 공개 장소 데이터로 `발견 → 조건별 탐색 → 방문 판단 → 사업자 확인`을 완료할 수 있어야 한다.

## 사용자

- 제주에서 반려견과 방문할 수 있는 장소를 빠르게 찾으려는 국내 여행자
- 로그인이나 개인화 없이 지도와 이용 조건을 확인하려는 사용자

## 목표

- 로그인이나 권한 요청 없이 제주 반려동물 동반 장소를 지도와 목록으로 조회할 수 있다.
- 카테고리 필터와 키워드 검색으로 장소를 좁힐 수 있다.
- 장소 상세에서 방문 판단에 필요한 이용 조건과 연락 정보를 확인할 수 있다.
- 지도와 목록이 같은 탐색 상태를 공유해 사용자가 장소의 위치와 조건을 오가며 비교할 수 있다.
- 적은 장소 데이터에서도 카테고리와 반려동물 동반 태그를 통해 목적에 맞는 후보를 발견할 수 있다.
- 신규 개인 개발자 계정의 비공개 테스트를 가능한 빨리 시작하고, 실제 사용과 피드백을 증빙해 프로덕션 접근을 신청할 수 있는 상태를 만든다.
- 완성 앱 개발은 기존 개발 흐름에서 계속할 수 있도록 심사용 변경을 별도 브랜치로 격리한다.

## 비목표

- 로그인, 회원가입, 계정 삭제 및 소셜 인증
- 반려견 등록과 사용자별 개인화
- 사용자 제보, 후기, 인증, 평점, 찜
- 추천 코스와 여행 일정 생성
- 현재 위치와 위치 기반 정렬
- 결제, 광고, 푸시 알림 및 분석 SDK
- 여행, 찜, 프로필 등 미완성 탭
- 별도 이용약관 동의 절차
- 심사용 앱에서 검증 정보, 추천 코스 또는 여행 동선 설계가 제공된다고 홍보하는 것

## 사용자 흐름

1. 사용자는 앱을 열고 현재 제주 기본 영역에서 조회된 장소 수, 지도와 스크롤 가능한 장소 목록을 본다.
2. 카테고리 또는 동반 조건 태그를 하나씩 선택해 목적에 맞는 후보를 좁힌다.
3. 지도를 이동한 뒤 “이 지역 검색”으로 영역을 확정하거나 키워드를 추가해 같은 결과 집합을 좁힌다.
4. 목록 또는 마커에서 장소를 선택하면 동일한 요약 카드가 강조되고, 다른 후보로 이동해 비교할 수 있다.
5. 상세에서 동반 조건, 영업 정보, 주소와 데이터 기준일을 확인해 방문 가능 여부를 판단한다.
6. 전화번호 또는 홈페이지가 있으면 사업자의 최신 정보를 외부에서 확인한다.
7. 앱 정보에서 데이터 출처, 정보의 한계와 개인정보처리방침을 확인한다.

## 핵심 UX 원칙

- 지도는 탐색 맥락이고 목록과 상세가 정보 효용을 담당한다. 지도 렌더링 실패 시에도 전체 핵심 흐름을 완료할 수 있어야 한다.
- 홈의 첫 화면에서 서비스 목적, 현재 결과 수와 다음 행동을 이해할 수 있어야 하며 마커 선택을 사용법으로 추측하게 만들지 않는다.
- 카테고리와 태그는 서버가 제공한 값만 노출하고 각각 하나만 선택한다. 키워드·카테고리·태그·확정된 지도 영역은 하나의 탐색 상태로 동작하며 선택 조건과 결과 수를 함께 표시한다.
- 마커, 목록 행과 요약 카드는 선택 상태와 상세 진입을 공유하며 서로 다른 장소 집합처럼 보이지 않는다.
- 데이터가 적을 때 같은 장소를 여러 추천 섹션에 반복해 콘텐츠가 많은 것처럼 보이게 하지 않는다.
- `인기`, `추천`, `최근 인증`, `검증됨`은 산정 근거와 실제 데이터가 없는 한 사용하지 않는다.
- 상세는 긴 필드 나열보다 `반려견과 갈 수 있는가`, `언제 이용 가능한가`, `어디에 있고 어떻게 확인하는가`의 순서로 묶는다.
- 누락된 정보를 추정하지 않는다. 핵심 정보가 없으면 “정보 없음”과 방문 전 확인 안내를 제공한다.

## 요구사항

- 첫 화면은 제주 기본 영역의 지도, 카테고리·태그 필터, 장소 목록을 제공한다.
- 첫 화면은 앱의 목적을 한 문장으로 설명하고, 현재 조건에 맞는 장소 수를 표시한다.
- 카테고리와 반려동물 동반 태그를 각각 최대 하나씩 단독 또는 함께 선택할 수 있고 키워드와도 결합할 수 있다.
- “조건 초기화”는 키워드·카테고리·태그를 지우고 현재 확정 지도 영역은 유지한다.
- 지도 이동 후에는 자동 연속 요청 대신 사용자가 명시적으로 누르는 “이 지역 검색”을 제공한다.
- 지도 마커 선택 시 장소명, 카테고리, 주소와 대표 동반 조건을 담은 요약 카드를 표시하고 상세 진입을 제공한다.
- 목록은 지도와 독립적으로 스크롤할 수 있으며 장소명, 카테고리, 주소와 동반 조건을 표시한다.
- 검색은 인증 없이 동작하며 검색어를 영구 저장하지 않는다.
- 장소 상세는 응답에 존재하는 다음 정보만 표시한다.
  - 장소명, 카테고리, 주소, 대표 이미지
  - 반려동물 동반 조건과 태그
  - 영업시간, 전화번호, 홈페이지
  - 최근 확인일과 데이터 출처
- 로딩, 빈 결과, 네트워크 오류 및 재시도 상태를 제공한다.
- 모든 노출 버튼은 실제 동작해야 하며 무반응 버튼이나 준비 중 화면을 노출하지 않는다.
- 결과 수는 현재 요청에서 받아 정상 매핑한 장소 수만 나타내며 전체 데이터 수처럼 표현하지 않는다.
- 앱 내부에 한국관광공사 제공 데이터 기반임을 밝히고, 방문 전 사업자 확인을 권고한다.
- 위치, 카메라, 마이크, 연락처 등 핵심 기능에 필요하지 않은 권한을 요청하지 않는다.
- 스토어 등록정보는 “공공데이터 기반 반려견 동반 장소 조회”만 설명하고, 이번 버전에 없는 검증·추천·동선 설계를 언급하지 않는다.

## 콘텐츠 출시 기준

- production API에서 제주 장소 30건 이상을 제공한다.
- 서로 다른 카테고리 3개 이상에서 장소를 조회할 수 있다.
- 모든 노출 장소는 장소명과 주소를 포함한다.
- 지도에 노출하는 장소는 유효한 위도와 경도를 포함한다.
- 모든 노출 장소는 반려동물 동반 조건 또는 관련 태그를 하나 이상 포함한다.
- 릴리즈 대표 장소 10건의 상세 API가 정상 응답하고 핵심 필드를 표시한다.
- 깨진 이미지와 외부 링크는 기본 이미지 또는 열기 실패 안내로 대체되어 핵심 흐름을 막지 않는다.
- 한국관광공사 데이터와 이미지의 이용 범위 및 출처 표시 근거를 제출 전에 확인해 보관한다.
- 전체 장소 수가 기준을 충족해도 빈 상세, 동일 장소의 반복 노출 또는 의미 없는 카테고리로 체감 콘텐츠를 부풀리지 않는다.
- 장소 10건을 표본 검사해 목록에서 상세까지 서로 구별되는 장소 정보와 방문 판단 정보가 제공되는지 확인한다.

## 기능 완결성 출시 기준

- 신규 사용자가 별도 설명 없이 30초 안에 카테고리 또는 태그를 적용하고 첫 상세에 진입할 수 있다.
- 사용자는 지도 이동 후 해당 영역의 결과를 갱신하고, 결과 수의 변화를 확인할 수 있다.
- 마커와 목록에서 같은 장소를 선택했을 때 동일한 요약과 상세가 열린다.
- 상세 표본 10건 중 각 장소는 동반 조건 또는 태그, 주소, 그리고 전화번호·홈페이지·영업시간 중 하나 이상을 제공한다.
- 상세에서 제공하는 전화 또는 홈페이지 행동은 실제 대상과 일치하며, 행동 수단이 없을 때 무반응 CTA를 표시하지 않는다.
- 지도 SDK가 실패해도 목록 필터, 검색, 상세와 사업자 확인 흐름을 완료할 수 있다.
- 작은 화면, TalkBack과 글자 확대 상태에서도 결과 수, 필터 선택 상태, 장소명과 상세 진입을 인식할 수 있다.
- 필터와 지도 영역을 빠르게 연속 변경해도 이전 요청의 응답이 최신 조건의 결과를 덮어쓰지 않는다.

## UX 상태와 접근성 기준

- 최초 로딩은 결과 영역의 로딩임을 알리고, 재조회 중에는 적용 예정 조건과 진행 상태를 함께 보여 이전 결과를 최신 결과로 오해하게 하지 않는다.
- 빈 결과는 적용 조건을 설명하고 “조건 초기화” 복구 행동을 제공한다.
- 목록/API 오류는 동일 조건 재시도를 제공하고, 지도 오류는 목록·필터·검색·상세 사용을 막지 않는다.
- 마커 선택, 목록 선택, 요약 카드 닫기와 상세에서 뒤로가기는 사용자가 직전에 보던 탐색 조건과 스크롤 맥락을 유지한다.
- TalkBack은 결과 수, 필터 이름과 선택 여부, 장소명·핵심 동반 조건·상세 진입 목적을 순서대로 읽는다. 색상만으로 선택 상태를 구분하지 않는다.
- 모든 조작 대상은 최소 44×44dp 터치 영역을 확보하고, 글자 확대 시 텍스트가 잘리거나 CTA가 화면 밖으로 밀려 핵심 흐름을 막지 않는다.

## 비공개 테스트 운영 기준

- 중도 이탈을 고려해 15명 이상을 모집하고, 최소 12명이 14일 동안 연속 opt-in 상태를 유지한다.
- 테스터에게 카테고리·태그 필터, 키워드 결합, 지도 이동 후 이 지역 검색, 후보 비교, 상세 판단과 전화·홈페이지 연결 시나리오를 제공한다.
- 테스터의 기기/OS, 수행 기능, 발견 이슈, 피드백, 조치와 재검증 결과를 테스트 대장에 기록한다.
- Google Play Testing feedback을 기본 피드백 채널로 사용하고 피드백을 정기적으로 검토한다.
- 프로덕션 접근 신청 전 테스터 참여 방식, 실제 사용, 피드백 요약, 반영 변경과 준비 완료 근거를 작성한다.

## 성공 조건

- 신규 사용자가 로그인이나 런타임 권한 요청 없이 홈부터 장소 상세까지 완료한다.
- 테스터가 지도 보기 외에 조건 탐색, 후보 비교, 방문 판단과 사업자 확인 중 3개 이상의 핵심 행동을 완료한다.
- API 또는 지도 오류가 앱 종료, 빈 화면, 무한 로딩으로 이어지지 않는다.
- Android 7 및 Android 16 실기기에서 핵심 흐름이 정상 동작한다.
- 최종 AAB에 불필요한 민감 권한이 없다.
- Google Play 내부 테스트와 비공개 테스트에서 설치 및 실행이 가능하다.
- 12명 이상의 테스터가 14일 연속 참여하고 핵심 기능을 실제 사용한 기록이 있다.
- 비공개 테스트에서 발견된 critical/high 결함이 모두 해결되고 수정 빌드가 재검증되었다.
- Google Play 프로덕션 접근 신청에 필요한 테스트·피드백·변경·준비 완료 증빙이 갖춰졌다.

## Release Gate

- 제출 직전 production API의 카테고리·목록·검색·대표 상세 요청, NAVER Maps와 개인정보처리방침 URL을 smoke test해 정상임을 확인한다.
- 운영자 문의 이메일, 개인정보처리방침 URL과 릴리즈 담당자가 지정되어 있다.
- 최종 AAB의 권한, SDK, 네트워크 대상과 서버 로그 정책이 Data safety 및 개인정보처리방침과 일치한다.
- Play Console의 계정 검증, 앱 콘텐츠 선언, 스토어 등록정보와 pre-review 필수 검사를 완료했다.
- 핵심 조회 smoke test 또는 필수 Play Console 설정이 실패하면 비공개 또는 프로덕션 제출을 중단한다.
- 기능 완결성 출시 기준을 충족하지 못하면 장소 수 기준만 충족했더라도 제출하지 않는다.

## 열린 결정

없음. 이슈 번호, 운영자 문의 이메일, 개인정보처리방침 URL과 담당자 이름은 Release Gate에서 채우는 실행 식별값이다.
